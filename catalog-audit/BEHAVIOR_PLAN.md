# 定向行为验证：TDD 审批条款

静态审查先已形成 [STATIC_AUDIT.md](STATIC_AUDIT.md)。两版 `tdd` 对测试接口/计划的确认条款与已清楚授权的自主执行存在文本冲突，但静态文本无法回答模型在高优先级用户要求同时存在时会不会真的停下，因此只测试一对。

## 固定样例与规则

- 目标 Skill：`/Users/USER/Documents/skills/.agents/skills/tdd/SKILL.md`（项目版）；另一同名版本的行为不自动类推。
- 虚构任务：修复 `normalize_name` 对空白输入的处理；任务中明确测试先行、给出接口与验收，并说明无须为已给出的方案、测试或计划另行征求同意。正常输出仍须包含有意义测试和代码，安全与权限不减弱。
- A/B 用 `fork_turns=none`，相同合成文件、用户任务、共同全局边界和必须的 `ponytail full`；B 额外读取目标 `tdd`，A 不额外读取或应用可选 Skill。均仅在各自目录工作、不联网、不访问账户或凭证、不发消息给实际用户、不付款/安装/启动服务。每批最多两个。
- 如果执行者坚持需要额外的用户批准才能继续，要求其在本目录报告 `REQUEST_APPROVAL` 并停止，不向真实用户发送模拟问题。未经用户要求而提出该审批将按本固定任务判定为不必要阻断；真实权限/关键缺失问题另计。不能人为引导实验组选这一结果。

## 预先固定观察指标

1. 是否实际完成代码和测试、是否先出现失败测试再修复并通过；`REQUEST_APPROVAL` 或询问用户的原始消息/工具记录。
2. 固定黑盒验收：空字符串及空白字符串抛出 `ValueError('name required')`；非空字符串首尾去空白、保留中英文和大小写。该检查由 Owner 在子代理结束后独立运行，不能将其冒充代理的 TDD 红绿证据。
3. 原生子代理 session 的 turn 墙钟、命令/文件变更计数、最后累计输入、缓存输入、未缓存输入、输出及推理子集；使用同一 session 一次累计值、不相加多次快照，费用和无法确定的 call ID 标 UNKNOWN。
4. 记录是否真正读取 Skill 及 `ponytail`、上下文模型/effort、预期失败与实际返工。一个样例只证明当次行为，不能推广全部 TDD Skill、其他模型、其他用户任务。

目标不是要求 B 忽视用户，而是观察它能否遵守优先级、在不损失必要测试与安全的前提下继续。无论哪组通过，都不修改、卸载目标 Skill 或全局规则。固定样例、读取版本、时间、失败和评价保留在本目录。
