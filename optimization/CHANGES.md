## 验证层

- 已写入：上述 26 份源文件。
- 静态检查：备份 SHA-256、UTF-8、标准 Psych YAML 解析、Skill 名称、无关元数据、引用增量、两份相同设计入口一致性通过，见 [validation.json](validation.json)。
- 原 bundled quick_validate.py 的默认 Python 缺少 PyYAML，未安装依赖、未冒称运行通过；其不识别的已有宿主扩展（hooks、triggers 等）保留，独立解析结果和范围已记录。
- 行为检查：交由原评估 Owner 对冻结快照独立配对；静态 PASS 不等于实际遵守，最终实测另附。

独立复核发现首轮 graphify 的 B2 仍写一次派发所有子 Agent，与其可选内联和并发上限说明有歧义；已在第二轮明确内联输出契约、条件性委派、限额分批与缺块恢复。同时修订 github-and-merge 引用中按现有 Key 选后端的残留建议。第二轮修改前分别备份，见 [revision-2/backup-manifest.json](revision-2/backup-manifest.json)；新冻结副本见 revision-2/after/user-graphify，原 frozen 输入未替换。该项仅静态复核，没有执行真实外部调用或越权行为试验。

## 保留的不确定性

- 会话入口描述被截断的来源仍 UNKNOWN，本次不改平台配置来猜修。
- 未验证所有几百个 Skill、所有组合或真实项目的长期效果。
- 没有因同名/同哈希就删除条目；兼容入口与注册关系可能有不同用途。
- 上游升级可能覆盖本机修订；当前运行会话未必会自动重读，不能把磁盘写入当作全体会话已加载。
- 未改运行中的 hooks 或自动化；保留声明不证明本机实际启用。

## 备份与回退

[backup-manifest.json](backup-manifest.json) 记录修改前独立副本、SHA-256、模式和时间；副本在本目录 backup 下保留绝对来源的目录结构。

回退前先核当前文件哈希是否仍等于 change-summary.json 的 sha256_after；若不同，说明可能有后续或并发变更，应先合并判断，不直接覆盖。只恢复已列明的对应文件，不递归重置 Skill 目录、注册、全局配置或其他资产。冻结输入 frozen 不因回退自动改写，确保实验仍可复核。

第三轮补查 graphify 的导出/转录/查询/监视/集成引用：凭证环境变量仅保留接口知识，不构成读取授权；只读查询不自动落盘或刷新反思记录；后台监视、MCP 和 hooks 需具体授权；无账户、凭证或服务实操。逐文件先备份；最新 graphify 冻结见 [revision-3/frozen-manifest.json](revision-3/frozen-manifest.json)，首轮三类编程试验输入仍不变。
